AD SERVER
  Google AdMob is the only ad server. Publisher ca-app-pub-4151367085462604.
  App ids live in AndroidManifest.xml (~1499765338) and Info.plist
  (~5043177104) and are never read from Dart.

  Unit ids come from the obfuscated .env via lib/env.dart, split per platform,
  and are selected in lib/core/services/ads/ad_config.dart:
      AdConfig.admobNativeUnit
      AdConfig.admobBannerUnit
      AdConfig.admobInterstitialUnit

  DEBUG / PROFILE builds serve Google TEST ads (AdConfig.admobTestMode).
  RELEASE builds always serve LIVE ads.
  AdConfig.showAdsInDebug = true  -> test ads render while debugging.
                          = false -> no ads at all on non-release builds.

  Qureka is NOT an ad server. It is a server-served promo creative bundle and
  it now has exactly ONE placement in the app (see section 4).

WIDGET      lib/core/services/ads/admob_native_ad_widget.dart
ENTRY       NativeAdSlot  (lib/core/services/ads/native_ad_list_inserter.dart)
TEMPLATE    TemplateType.small — a single list-row strip (icon + headline +
            Ad badge + CTA). Height is derived from the slot width, NOT a
            constant: (width - 20) / 4 + 20, floored at 96.
            TemplateType.medium is still supported and is a fixed 350dp.

CADENCE     Single-column lists : ad after item 1, then every 10  (1, 11, 21…)
            Grids / masonry     : ad after item 10, then every 10 (10, 20, 30…)
            Never after the final item.
            Defined once in native_ad_list_inserter.dart — do not hand-roll.

BEHAVIOUR   Zero height until an ad is live, and never shrinks back. Collapses
            silently on failure. Keep-alive across scroll recycling. The load
            is deferred until the route's push transition finishes.

--- 3a. CALL ENDED — chat/auth/controller/call_controller.dart:2363 -------------
  Trigger    _showCallEndedInterstitial(), reached from
             _navigateBackFromCallScreen() (:2342), which 7 teardown paths call
             (:1740, 1962, 1992, 2030, 2195, 2235, 2249) plus one direct call
             at :2229 for a branch that returns before navigating.
             Caller AND callee both reach it, on Android and iOS.

  Gate       _wasCallConnected — set true in _startCallTimer() (:3745) the
             moment the call actually connects, reset at :827 and :1093 when a
             new call starts.
               * PICKED UP + ended  -> ad shows
               * missed / rejected / unanswered -> nothing
             The flag is CONSUMED on read (:2367-2368), so however many of the
             8 paths reach teardown, the ad fires exactly ONCE per call.

  Timing     400 ms delay so it overlays the post-call screen (chat / home)
             rather than the call UI mid-dismiss. Fire-and-forget — it can
             never block teardown.

  Frequency  NOT session-capped. One per connected call is the accepted shape
             for a deliberate, bounded task.

--- 3b. RIDE COMPLETED — ride_booking/view/ride_completed_screen.dart -----------
  Trigger    _finish() — the single exit from the ride summary; both "Submit"
             and "Skip" land there.
  Timing     Fires as the customer LEAVES the summary, never over it. The fare
             and rating prompt are the receipt for a ride just paid for.
  Frequency  Session-capped, shared budget (see 3d).

--- 3c. ORDER PLACED — chat/view/orders_chat/widget/waiting_for_payment_dialog.dart
  Trigger    showOrderPlacedDialog(), after the dialog closes.
  Timing     After dismissal, never over the confirmation — an ad over a payment
             receipt is the pattern AdMob treats as interrupting a transaction.
  Frequency  Session-capped, shared budget (see 3d).

--- 3d. THE SHARED SESSION BUDGET ----------------------------------------------
  API        InterstitialAdManager.instance
                 .showInterstitialOncePerSession(kOrderBookingInterstitialKey)

  3b and 3c share ONE key, so a customer who finishes a ride AND places an
  order in the same session sees ONE ad, not two.

  The key is spent only when an ad ACTUALLY showed (showInterstitial returns
  bool). A no-fill must not burn the session's one slot, or the placement
  quietly stops earning on exactly the days inventory is thin.

      A banner over a full-bleed vertical video player is a mis-click factory

      right unit is rewarded, or a native-in-feed card BETWEEN reels — its own
      piece of work.

      Message bubbles. An ad card there reads as a message from the shop.

      Only the Chat tab carries a banner. One per Connect screen is enough.

  Any screen mid-transaction (checkout, payment, call UI)
      Ads fire only AFTER the user leaves these.
