6. CORRECTION TO YOUR GAP 4 RESPONSE
================================================================================

You wrote:

  "The lat/lon string-parsing you cited at viewBusinessProfileModel.dart:454 is
   a DIFFERENT, nested object from `business_location` — worth confirming on
   your side which payload that parser is actually reading."

We confirmed. It is not a different object. Lines 448-465 of that file are:

    class BusinessLocation {                 // line 448
      BusinessLocation.fromJson(dynamic json) {
        lat = double.parse((json['lat'] ?? '0.0').toString());   // line 454
        lon = double.parse((json['lon'] ?? '0.0').toString());   // line 455

and it is constructed from exactly one place:

    businessLocation = json['business_location'] != null
        ? BusinessLocation.fromJson(json['business_location']) : null;

There is only one BusinessLocation class in the file. So that parser IS reading
`business_location`.

This does not necessarily mean the schema is wrong — `.toString()` then
`double.parse` also succeeds on a real JSON number, so the coercion may simply
be defensive and has never been exercised. But the reasoning you used to dismiss
it ("that's a different payload") does not hold, so GAP 4 should be re-checked
against an actual response body rather than the schema alone.

Everything else in your GAP 4 answer we accept: if `referral_points` and
`total_ratings` are Numbers on the wire, our coercions are belt-and-braces and
we will leave them.
