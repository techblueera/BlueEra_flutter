GA4 CUSTOM DEFINITIONS - BlueEra          (fill-in list, 13 entries)
================================================================================
Property : the one linked to Firebase project blueera-50c05
Where    : analytics.google.com > Admin > Data display > Custom definitions
Source   : lib/core/services/analytics_service.dart + its call sites

The console form has exactly four fields. Copy each block below into it:

    Dimension name    <- free text, must be UNIQUE across the property
    Scope             <- dropdown: User / Event / Item
    Description       <- free text, optional
    Event parameter   <- MUST match the app string exactly (lower case,
                         underscores). At Scope=User this field is instead
                         labelled "User property".

Scope "Item" is for ecommerce item arrays - BlueEra sends none, so it is
never used below.

Registration is NOT retroactive: data collected before you create these stays
unqueryable in reports. Create them before gathering real traffic.

is what the "(event)" / "(user)" suffix is for.

================================================================================
C. DO NOT CREATE
================================================================================
Standard GA4 parameters - already in reports, creating them wastes quota:
    search_term     (search)
    method          (login, sign_up)
    screen_name     (screen_view)

Sent by the app but deliberately NOT registered - unique per event, so every
value becomes its own row and GA4 collapses the excess into "(other)",
corrupting totals. Use DebugView or the BigQuery export for these instead:
    order_id        (ride_requested)
    job_id          (job_post_published)


================================================================================
D. AFTER SAVING
================================================================================
Up to 24h before these populate reports, and only for data collected from
now on. DebugView shows the raw parameters immediately whether registered or
not - so use DebugView to confirm the app sends the right names, and the
reports a day later to confirm registration took.

Quota used: 10 of 50 event-scoped, 2 of 25 user-scoped, 1 of 50 metrics.
